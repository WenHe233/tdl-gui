## v0.1.9 二维码登录回归（2026-10-05）

- 本机 Windows 11 全新会话复现：TCP 连接、密钥交换成功后，gotd 报 `created too far in future: message rejected`，始终不能进入二维码请求。与是否曾登录无关。
- 当前网络中 NTP/UDP 超时；通过同一 HTTP 代理读取 Telegram HTTPS 响应的 Date 后，应用内校时使全新会话在 5.3 秒内取得二维码 PNG。未修改 Windows 时间，未扫码或授权测试账户。
- 本地无响应 SOCKS5 代理：45.0 秒发出 `login.error`；同一个 worker 改用正常代理后能够取得二维码，再取消登录成功。
- 自动测试覆盖等待后台锁时超时、取消后的锁释放、显示登录提示后停止首次响应计时、Windows 系统代理格式解析、时钟快/慢十分钟的校正和无效 Date 拒绝。
- 尚未在用户报告问题的 Win10 设备上运行；不能据本机结果认定每台 Win10 设备均由时间偏差导致。请用新版本复测；若仍失败，记录最后显示的连接阶段和完整错误。

登录页可填写 HTTP/SOCKS5 代理地址，留空为直连；新配置默认读取已启用的 Windows 静态系统代理（不执行 PAC）。该设置也用于浏览和下载。HTTPS 自动校时用于内置登录及图片客户端，独立 tdl 引擎仍沿用其 NTP 配置。

## 专用测试聊天准备

请在收藏夹或私有测试群依次放入：

1. 一张 JPG 和一张 PNG。
2. 一个短 MP4、一个音频或语音。
3. 一个 PDF 和一个 ZIP。
4. 一组包含 2–3 张图片的相册。
5. 将第一张 JPG 再转发一次，用于同聊天去重。
6. 一个超过设定单文件上限的文件。
7. 文件名包含中文、Emoji 和 Windows 非法字符语义的样例。

在本机运行 GUI 后扫码或输入验证码即可。不要把验证码、两步验证密码或会话文件发到对话中。

联调检查：聊天列表可见；扫描数量正确；日期、类型、关键词和大小筛选正确；相册成组显示；重复媒体只保存一份；固定清单排除项不会下载；暂停后已完成项跳过、半成品重下；最终文件大小与源样例一致；再次扫描只补齐新增或失败项。
